# CRITICAL

## C1 — Privilege escalation: any `edit_posts` holder rewrites ANY framework page
**`src/Rest.php:598-600`** (`can_save`) and **`:608-614`** (`handle_save`)

```php
public static function can_save(): bool {
    return current_user_can( Editor::CAPABILITY ) && Roles::can( 'editor.open' );
}
```
`Editor::CAPABILITY` is `edit_posts` — a **site-wide** capability. There is **no
`current_user_can( 'edit_post', $post_id )` anywhere in Rest.php** (verified: 0 matches).

### CONFIRMED — executed end to end
```
page #244 'about', node 'about-eyebrow'
acting as contributor (edit_post = DENIED)
save response ok = TRUE
canonical AFTER contains marker: YES
>>> VULNERABLE: contributor rewrote a page WP denies them
```
Capability matrix, measured:

| role | `edit_posts` | `editor.open` | `can_save()` | WP `edit_post(#266)` |
|---|---|---|---|---|
| contributor | Y | Y | **YES** | **n** |
| author | Y | Y | **YES** | **n** |
| subscriber | n | Y | no | n |

**Aggravating:** `Compiler::write_post_content_raw` suspends kses for the write, so a
Contributor's content also bypasses the `unfiltered_html` restriction their role normally carries.

**Repro:** as a Contributor, `POST /wp-json/s5/v1/pages/{any_id}/save` with
`{"mode":"slots","slots":[{"node":"<id>","type":"text","value":"..."}]}`.
**Expected:** 403. **Actual:** 200, page rewritten.
**Fix:** add `current_user_can( 'edit_post', $post_id )` in `handle_save` after the post lookup.

## C2 — Five XSS vectors bypass the validator AND execute in a real browser
**`src/Validator.php:183-207`** — the `javascript:` rule's XPath is `//*[@href or @src]` and the
inner loop is hardcoded to `array( 'href', 'src' )`. `ltrim()` at `:192` strips only *leading*
whitespace, never control characters embedded inside the scheme.

### CONFIRMED — validator verdict (live) + browser execution (Chromium)

| Vector | Validator | Browser |
|---|---|---|
| `<button formaction="javascript:...">` | **blocks=NO** | **EXECUTED** |
| `<iframe srcdoc="&lt;script&gt;...">` | **blocks=NO** | **EXECUTED** |
| `<svg><a xlink:href="javascript:...">` | **blocks=NO** | **EXECUTED** |
| `href="java<TAB>script:..."` | **blocks=NO** | **EXECUTED** |
| `href="java<NEWLINE>script:..."` | **blocks=NO** | **EXECUTED** |

Control set — these correctly block: `onclick`, `ONCLICK`, `OnClick`, `onerror`,
`onload`, svg-nested `onclick`, `javascript:` in `href`, mixed-case `JaVaScRiPt:`, `<script>`.

This is the **same bug class** the prior audit fixed for `on*` handlers, left open on four other
attributes. Canonical HTML is served byte-clean (no output-layer kses), so a stored payload
reaches every logged-out visitor.

**Fix:** extend the URL rule to `formaction`, `xlink:href`, `action`, `poster`, `data`; add a rule
for `srcdoc`; strip `[\x00-\x20]` throughout the value before the scheme comparison.

# HIGH

## H1 — Silent data loss: staged text edits discarded by any auto-saving operation
**`assets/editor/editor.js:48-56`** (global `markClean`) vs **`assets/editor/panel.js:30,374`**

`structure.js:381` (delete/duplicate) and `styleaxes.js:110` (style slider) call the **global**
`shell.markClean()`, which clears `state.dirty` and disables Save — but **never touches
`slotEdits`**, which only `doSave()` clears on success.

### CONFIRMED — reproduced in Chromium
```
step1  staged=[n1]  dirty=true   saveEnabled=true
step2  slotEditsStillHeld=[n1]  stateDirty=false  saveButtonEnabled=false
step3  wouldWarnOnClose=false
>>> DATA LOSS CONFIRMED
```
**Repro:** type into a Text field → without saving, delete any node in the structure tree.
**Actual:** Save greys out with the edit still buffered; the preview reloads and reverts the text;
`beforeunload` will **not** warn because `state.dirty` is false. The typing is gone silently.

This is very likely the true source of the original *"nothing is getting saved"* report — the
label flip was the visible symptom; this is the mechanism that actually loses work.

**Fix:** make `markClean()` refuse to clear while `slotEdits` is non-empty, or give structure ops
their own busy-state that does not touch the shared dirty flag.

## H2 — Dirty-dot indicator dies permanently after the first save
**`panel.js:328,334,356`** + **`editor.js:25`** + **`templates/editor.php:95`**

The dot is a **child** of the Save button:
```html
<button data-s5-update disabled><span class="dirty-dot" data-s5-dirty style="display:none"></span> Save</button>
```
`editor.js:25` captures a **live element reference** once at init. `panel.js:356`
(`textContent = 'Saving…'`) and `:334` (`innerHTML = saveLabelHtml`) both **destroy and re-parse**
that subtree, orphaning the tracked node.

### CONFIRMED — reproduced in Chromium, real boot sequence
```
step2_dotAfterFirstEdit   = inline-block   (works)
step3_trackedNodeDetached = true
step4_dotAfterSecondEdit  = none           (dead)
step4_buttonEnabled       = true
>>> BUG CONFIRMED: dot never returns after first save
```
The button still enables, so edits are savable — but the visual "unsaved" cue is gone for the rest
of the session. Same breakage after a failed save or network error.

**Fix:** have `restoreSaveButton()` re-query `[data-s5-dirty]`, or keep the label in a dedicated
child span and never overwrite the button's whole innerHTML.

## H3 — `mode:slots` and `mode:class` bypass the roles matrix entirely
**`src/Rest.php:625-630`, `:663-668`**

7 of 9 save modes call `Roles::can()`. These two do not. The matrix keys `editor.content` and
`editor.style` **exist in `Roles.php:65-72` and are referenced nowhere in `Rest.php`**.

An admin who disables content/style editing for the client role gets a UI that hides the tabs while
the endpoint still accepts the writes — violating the framework's own stated law
("hidden AND blocked", `Roles.php:12-16`).

---

## H4 — Component save validates against a vocabulary it forbids you to update
**`src/Rest.php:539-568`**

The endpoint discards any `css` payload (CSS is read-only there), then validates the HTML against a
vocabulary derived partly from that untouched `style.css`. Adding `<div class="badge">` and
`.badge{}` in one save → CSS silently dropped, HTML rejected 422 as unknown class, with no message
explaining the required order.

# MEDIUM

## M1 — Shortcode injection: plain text slots reach `do_shortcode()`
**`Rest.php:1493` → `Compiler.php:415` → `templates/canvas.php:54`**

### CONFIRMED
```
esc_html('[gallery id=1]') = '[gallery id=1]'   -> brackets survive: YES
needs_dynamic_pass(): TRUE  (would do_shortcode at request time)
validator findings on shortcode text: 0
```
`esc_html` does not escape `[` or `]`. A client-role user typing `[gallery]` into a **plain text
field** flips the page to dynamic and executes that shortcode server-side for every visitor.
Impact scales with installed plugins. The validator raises nothing.

## M2 — `/tokens` CSS filter weaker than `/element` CSS filter
**`Styles.php:81-83`** blocks `; { } <` but not `javascript:` / `expression()` / `data:` —
all of which `ElementStyles.php:524` **does** block. Two doors write the same
`dist/s5.css` bundle under different policies. Impact bounded (external stylesheet, and
`url(javascript:)` is dead in modern browsers), but it is a policy divergence in a
"one door" architecture.

## M3 — `$dev` flag missing on component and template saves
**`Rest.php:359`, `:554`** — page save computes role-aware `$dev`; these two hardcode ERROR, so a
Developer hits the hard closed-vocabulary wall the role-aware validator exists to remove.

## M4 — "Open in / New tab" control is inert
**`panel.js:156-160`** — no handler, stages nothing, POSTs nothing, sitting between two working
fields. The server **does** allow `target` (`Rest.php:57`). User sets "New tab", clicks Save, gets
"Updated", setting silently discarded.

## M5 — Diagnostics stack unboundedly, then vanish silently
**`panel.js:402-411`** — nothing clears prior `.s5e-diagnostics`; N failures render N boxes, all
erased by the next selection (`renderFields` wipes `panelBody`).

## M6 — Empty "Save rejected" box on nonce expiry
**`panel.js:373-384`** — `r.status` is captured but never read. A 403 `rest_cookie_invalid_nonce`
is valid JSON with no `diagnostics`, so the user gets a "Save rejected" header with **zero**
explanatory lines. Correct behaviour otherwise: `slotEdits` preserved, button re-enabled.

## M7 — Toasts overlap exactly
**`editor.js:295-311`** + **`editor.css:726`** — every toast is `position:fixed; right:20px;
bottom:20px` with no stacking offset. Two within 2s render superimposed.
*(Verified sound: `root` scope, script load order, z-index 300 above all layers, `pointer-events:none`.)*

# Test coverage — the structural finding

**`tests/acceptance-editor.sh` is named for the editor but tests the save *door*, not the *editor*.**

- **Zero** JS unit-test infrastructure. No Jest/Vitest/jsdom. **~3,680 lines of editor JS** have no unit coverage. PHPUnit exists but its only test is `assertTrue(true)`, and it is not in the gate.
- **Zero** assertions on any save-UI identifier — verified by grep across `tests/`:
  `data-s5-update`, `s5e-toast`, `slotEdits`, `Nothing to save`, `Updated`, `restoreSaveButton` → **0 hits each**.
- **Zero** coverage of the four structure modes — `insert`, `reorder`, `delete`, `duplicate` → **0 hits each**, at *any* layer. `delete` is irreversible.
- Slot types: only `text` is exercised. `rich`/`link`/`img`/`src`/`list` have **no** save coverage.
- No Playwright script drives the editor. The strongest browser assertion in the repo is
  `locator('[data-s5-editor]').count() > 0`.
- The suite calls `Rest::handle_save()` **in-process**, so nonce, cookies, HTTP status and
  `cfg.saveUrl` localization are all unverified. A broken nonce would 403 every save in the real
  editor with the gate still green.

**Both H1 and H2 shipped through a fully green 24-suite gate.** That is the coverage gap, stated plainly.

### Cheapest high-value closures
1. Extend `tests/fixtures/editor-probe.php` with the 4 structure modes + 5 missing slot types *(no browser needed)*.
2. Add a real authenticated `curl` against the REST route to cover nonce/transport *(no browser needed)*.
3. Add a Playwright editor suite — infrastructure already exists (`acceptance-roles-login.sh` demonstrates the bash-wraps-node pattern).
4. Regression tests for C1, C2, H1, H2 specifically — each must fail before its fix.
